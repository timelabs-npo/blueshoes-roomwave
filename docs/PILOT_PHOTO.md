# Photo lane handoff

`PhotoMapAnalyzer.makeSample(luminance:width:height:saliency:)` is pure Foundation. It accepts row-major 8-bit luminance at 8...128 pixels per dimension and optional matching finite 0...1 attention values. It rejects invalid dimensions/counts/attention and featureless pictures (range below 12/255 or standard deviation below 3/255); attention cannot rescue a blank image.

The deterministic algorithm contrast-stretches luminance, computes Sobel gradients and 3x3 local contrast, then aggregates **every** pixel into at most 64x64 cells. Feature-weighted centroids and gradient offsets change horizontal placement; brightness, edges, local contrast and attention change height. Output is quantized to 0.001 game units, at most 4,096 points, marked `photoDerived`. The stable capture label is a local version label, not a unique identifier or photo hash. Same pixel and attention arrays give the same entire sample. No randomness, filenames or metadata influence geometry.

This is a styled 2.5D relief field, **not calibrated depth, room measurement, photogrammetry or a reconstructed scene**. Bright regions become taller by a styling rule; a single photo cannot establish their physical distance. Colored pictures with equal luminance may produce the same sample. Vision/device/decoder changes can change native attention/pixels; determinism applies to the core's identical input arrays, not all OS versions.

`@MainActor PhotoMapImporter.sample(from: Data) async throws -> ScanSample` is ready for the coordinator's PhotosPicker call. It accepts one complete still image, at most 20 MiB, 16,384 pixels per source side and 50 million source pixels (including typical 48 MP photos). It checks source bounds before ImageIO thumbnail decoding, applies EXIF orientation (including UIImage mirrored variants), preserves aspect ratio and caps analysis at 128 pixels per side. If the resulting short side is below 8 pixels, import fails rather than stretching it. Animated/multiframe images and incomplete data fail explicitly.

ImageIO objects, sRGB RGBA conversion, local Vision attention and core analysis run in a detached worker. Only Sendable `Data` and `ScanSample` cross actor boundaries. Cancellation propagates to the worker and is checked between synchronous stages and before return. A running synchronous decoder/Vision request is not immediately interrupted. Pixels are composited over white before Rec.709 display-encoded luma extraction, so transparent hidden RGB contributes no structure. Vision float attention is resampled to analysis dimensions; unsupported buffers, invalid values or request errors fall back to contrast/gradient/local-edge features. No remote inference, upload, file persistence, EXIF export or photo/capture-ID export is implemented. Source bytes and temporary buffers remain local and are released after analysis; this is not a secure-memory-erasure guarantee.

The coordinator owns picker/UI integration, normalization, final-track generation/preview and export. Export only the final `ChallengeDescriptor`/track, never this local `ScanSample`, photo bytes or attention buffers. Existing synthetic and ARKit sources are untouched. Downstream gameplay must use the actual point distribution/height cues as required by the pilot contract.

This reference checks numerical expectations only: it does **not** execute, compile or validate the Swift implementation.
